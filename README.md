## Технологічний стек

* **Платформа:** .NET 10 (ASP.NET Core Web API)
* **ORM:** Entity Framework Core 10 (PostgreSQL Provider)
* **База даних:** PostgreSQL 16
* **Конвенція іменування БД:** `EFCore.NamingConventions` (автоматичний `snake_case` без лапок у SQL)
* **Обробка помилок і результатів:** `ErrorOr` (патерн Result / Railway-Oriented Programming)
* **Контейнеризація:** Docker, Docker Compose (Multi-stage build)

## Правила розрахунку вартості оренди

Вартість оренди зали коригується відповідно до часового діапазону (коефіцієнти задаються в конфігурації `appsettings.json` у секції `PricingRules`):

* **Ранкові години (06:00 – 09:00):** знижка **10%** (множник `0.90`).
* **Стандартні години (09:00 – 12:00, 14:00 – 18:00):** базова вартість (множник `1.00`).
* **Пікові години (12:00 – 14:00):** націнка **15%** (множник `1.15`).
* **Вечірні години (18:00 – 23:00):** знижка **20%** (множник `0.80`).

> Додаткові послуги (проєктор, звук, Wi-Fi) мають фіксовану ціну за бронювання та додаються до вартості зали без урахування часових множників.

## Документація API маршрутів

Базовий маршрут контролера: `/api/halls`

### 1. Створення конференц-залу
Створює новий зал із прив'язкою доступних послуг.

* **Метод:** `POST`
* **URL:** `/api/halls`
* **Приклад тіла запиту:**
  ```json
  {
    "name": "Зал D",
    "capacity": 80,
    "costPerHour": 2500,
    "amenityIds": [1, 2]
  }
  ```
* **Відповіді:**
  * `201 Created` — Зал створено. Повертає заголовок `Location: /api/halls/{id}` та об'єкт:
    ```json
    {
      "id": 4,
      "name": "Зал D"
    }
    ```
  * `400 Bad Request` — Вказано неіснуючі ID послуг.
  * `409 Conflict` — Зал із такою назвою вже існує.

---

### 2. Отримання зали за ID
Повертає коротку інформацію про конкретний конференц-зал.

* **Метод:** `GET`
* **URL:** `/api/halls/{id}`
* **Відповіді:**
  * `200 OK` — Дані зали успішно знайдено:
    ```json
    {
      "id": 1,
      "name": "Зал А"
    }
    ```
  * `404 Not Found` — Зал із вказаним ID не знайдено.

---

### 3. Редагування інформації про зал
Оновлює параметри зали або синхронізує перелік послуг. Підтримує часткове оновлення (nullable поля).

* **Метод:** `PUT`
* **URL:** `/api/halls/{id}`
* **Приклад тіла запиту:**
  ```json
  {
    "name": "Зал D Преміум",
    "capacity": 85,
    "cost": 2700,
    "amenityIds": [1, 2, 3]
  }
  ```
* **Відповіді:**
  * `200 OK` — Дані успішно оновлено.
  * `400 Bad Request` — Передано невалідні ID послуг.
  * `404 Not Found` — Зал не знайдено.

---

### 4. Видалення конференц-залу
Видаляє зал за ID за умови відсутності активних або запланованих бронювань.

* **Метод:** `DELETE`
* **URL:** `/api/halls/{id}`
* **Відповіді:**
  * `204 No Content` — Зал успішно видалено.
  * `404 Not Found` — Зал не знайдено.
  * `409 Conflict` — Зал має активні бронювання і не може бути видалений.

---

### 5. Пошук доступних залів
Пошук залів за мінімально необхідною місткістю та відсутністю часових перетинів у розкладі.

* **Метод:** `POST`
* **URL:** `/api/halls/search`
* **Приклад тіла запиту:**
  ```json
  {
    "startTime": "2026-10-15T10:00:00Z",
    "endTime": "2026-10-15T14:00:00Z",
    "capacity": 50
  }
  ```
* **Відповіді:**
  * `200 OK` — Список доступних залів із закріпленими послугами:
    ```json
    {
      "halls": [
        {
          "id": 1,
          "name": "Зал А",
          "capacity": 50,
          "costPerHour": 2000,
          "amenities": [
            { "id": 1, "name": "Проєктор", "cost": 500 },
            { "id": 2, "name": "Wi-Fi", "cost": 300 }
          ]
        }
      ]
    }
    ```
  * `400 Bad Request` — Початок пізніше кінця інтервалу, пошук у минулому або місткість <= 0.

---

### 6. Бронювання залу
Створює запис бронювання для конкретної зали, валідує доступність зазначених послуг, перевіряє часові колізії та фіксує підсумкову вартість.

* **Метод:** `POST`
* **URL:** `/api/halls/{hallId}/bookings`
* **Приклад тіла запиту:**
  ```json
  {
    "date": "2026-10-15T10:00:00Z",
    "durationMinutes": 120,
    "amenityIds": [1, 2]
  }
  ```
* **Відповіді:**
  * `200 OK` — Бронювання успішно підтверджено:
    ```json
    {
      "totalCost": 4800.00
    }
    ```
  * `400 Bad Request` — Невалідна тривалість (<= 0), дата в минулому або вказані послуги недоступні для цієї зали.
  * `404 Not Found` — Зал не знайдено.
  * `409 Conflict` — Обраний часовий інтервал уже зайнятий іншим бронюванням.

---

### 5. Бронювання залу
Створює запис бронювання, фіксує підсумкову ціну з урахуванням знижок і послуг.

* **Метод:** `POST`
* **URL:** `/api/hall/books/{hallId}`
* **Приклад тіла запиту:**
  ```json
  {
    "date": "2026-10-15T10:00:00Z",
    "durationMinutes": 120,
    "amenityIds": [1, 2]
  }
  ```
* **Відповіді:**
  * `200 OK` — Підтвердження бронювання:
    ```json
    {
      "totalCost": 4800.00
    }
    ```
  * `400 Bad Request` — Невірна тривалість, минула дата або послуги недоступні для цієї зали.
  * `404 Not Found` — Зал не знайдено.
  * `409 Conflict` — Слот уже зайнятий іншим бронюванням.

## Розгортання (Docker)

Проєкт повністю налаштовано для запуску в Docker.

### 1. Налаштування середовища
Створіть файл `.env` у кореневій директорії поруч із `docker-compose.yml` та скопіюйте вміст файлу  `.env.example`  :

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
POSTGRES_DB=abptask
```

### 2. Запуск контейнерів
```bash
docker compose up --build -d
```

### 3. Автоматична ініціалізація
* Контейнер API очікує успішного проходження перевірки `healthcheck` від PostgreSQL.
* Під час старту автоматично застосовуються міграції бази даних через `db.Database.Migrate()`.
* Якщо база порожня, додаються початкові зали та послуги.

### 4. Зупинка
```bash
docker compose down
```
Для повного очищення разом із volume даних:
```bash
docker compose down -v
```
